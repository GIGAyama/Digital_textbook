## 「教科書と指導書を持ち歩く」の追記について（2回目の納品）

初稿はプリントの提示と丸つけだけで書いていて、**このアプリが本来いちばん想定していた使い方**、つまり教科書と指導書をスキャンして先生用端末やスマートフォンに入れ、どこでも教材研究と進度の確認ができるようにする、という話が抜けていました。そこを次の4か所で足しています。

- 「はじめに」に、荷物と教材研究の場所についての段落を1つ足しました。アプリの一行紹介も「スキャンした教科書や指導書も、ふだん印刷しているプリントも、同じ棚に並びます」に書きかえています
- 見出し「📚 教科書と指導書を、端末のなかに入れて持ち歩く」を新設しました（📱 と ✍️ のあいだ）
- 「導入のメリット」を三つから四つに増やし、一つ目を「教材研究をする場所が選べる」にしました。以降の番号もずらしてあります
- 「使い方のガイド」に、スキャンした教科書の読みこみ（手順4）とドライブでの持ち出し（手順12）を足しました。「管理者向け」の3番にも、共用端末に教科書を残さない話を一文足しています

### 文体の約束から外れたところが2つあります

どちらも意図的です。戻したい場合の手当てもあわせて書きます。

1. **見出しが9本になりました**（基本6本＋追加3本。上限は追加2本）。想定していた使い方そのものなので、既存のスタンプ・共有の節を削るより、1本足すほうが読み手のためになると判断しました。8本に戻すなら、この節を「📱 このアプリでできること」の後半に見出しなしで畳むのがいちばん傷が浅いです。
2. **本文が 9,506 字になりました**（初稿は 7,789 字。目安は 7,000〜9,000）。9,000 に収めるなら、新設した節の最後2段落（ドライブの上書きの注意と、スキャンの扱いのお願い）が削りやすい候補です。ただしこの2つは、実際に使う先生がつまずく／気にする点なので、私としては残すことをおすすめします。

太字0か所、表0行、禁止記号0か所、絵文字は見出しのみ、箇条書きは手順の2か所だけ、という残りの約束は追記後も守っています。

### 撮り足すとよい画像（今回は撮っていません）

初稿の撮影環境（`.tmp-shots/`）は納品時に消してあるため、今回の追記ぶんは文章だけです。次の3点を実機で撮ると、この節の説得力が上がると思います。

### タイトルも見直したほうがよいかもしれません

いまのタイトルは「このプリント、そのまま大きく映したい」で、提示の話だけを掲げています。想定していた使い方を前に出すなら、たとえばこのあたりです。型は初稿と同じ `「困りごと」＋持ち味＋アプリ「名前」` のままにしてあります。

- 「指導書、重くて持ち帰れない」教科書もプリントもPDFで持ち歩けるアプリ「デジタル教科書メーカー」
- 「あの単元、どこまで進んだっけ」教科書と指導書を端末に入れて持ち歩けるアプリ「デジタル教科書メーカー」

どちらを掲げるかで、読み手が変わります。提示と丸つけを前に出すと日々の授業をしている先生に届き、持ち歩きを前に出すと教材研究の時間を取れずにいる先生に届くはずです。記事は両方を書いてあるので、掲げるほうだけ選べば大丈夫です。

## note への貼りかた

1. 記事本文の1行目（`# 教室で…`）を、note のタイトル欄に貼ります。本文には入れません。
2. 2行目以降を本文欄に貼ります。`##` の見出しはそのまま見出しとして認識され、note が目次を自動で作ります。
3. 画像は自動では入りません。`![...](images/xx-....png)` の行のところで、下の対応表を見ながら手動でアップロードしてください。
4. キャプション（画像の下の一行）は、貼りつけたあと note のキャプション欄へ移してください。本文に残したままでも読めますが、キャプション欄に入れたほうが見た目が整います。
5. ハッシュタグは `#GIGAスクール` `#ICT教育` `#小学校` `#教員` `#デジタル教科書` あたりが合うと思います。
6. 公開前に、アプリの URL が生きているかを一度確認してください。

### 画像について、断っておくこと

- **サンプルの PDF は撮影用に作った架空のプリントです。** 実在の教科書・ワークではありません。3年算数「あまりのある わり算」4ページと、4年国語「だんらくの つながり」2ページを、撮影のためにその場で作りました。
- **共有画面（`19-share.png`）の URL は `http://` で写っています。** 本番は `https://digital-textbook.giga-school.com/` です。撮影中だけ本番のホスト名を手もとのサーバーに向けており、そこだけ本番と見た目が異なります。気になる場合は、実機で撮り直してください。
- **「データを受信しています」のモーダルは撮れませんでした。** 手もとの環境では受信が速すぎて（1秒未満）、モーダルが表示される前に完了してしまいます。実際の校内ネットワークでは表示されるはずなので、必要なら実機で撮り足してください。20番はその直後の「受け取り終わった画面」です。
- 子どもの端末の画面（`20`, `21`）は、先生の端末とは別のブラウザプロファイルを立ち上げて、本当に2台つないで撮ったものです。合成ではありません。

## 撮り直すときの手順

撮影に使ったスクリプトは `.tmp-shots/` に置いて作業し、納品時に消しました。同じものを作り直す場合の手順です。

1. 撮影の道具をまとめて入れます。`npm i --no-save playwright peer`
2. 本番と同じ見た目にするため、本番のホスト名を手もとに向けます。`echo "127.0.0.1 digital-textbook.giga-school.com" >> /etc/hosts`
3. 共有機能を撮るには、待ち合わせ用のサーバーを手もとに立てます。`node <skill>/scripts/peer-server.mjs 9000`
4. アプリ側の接続先を一時的に差しかえます。`src/App.jsx` の `new window.Peer()` を2か所とも `new window.Peer(undefined, { host: '127.0.0.1', port: 9000, path: '/', secure: false })` にして、`index.html` の CSP の `connect-src` に `http://127.0.0.1:9000` と `ws://127.0.0.1:9000` を足します。
5. `npm run build` して、`node <skill>/scripts/serve.mjs dist 80 /Digital_textbook/` で配ります。
6. `node <skill>/scripts/capture.mjs shots.mjs --base http://digital-textbook.giga-school.com/ --out shots` で撮ります。
7. **4の差しかえを必ず戻して、`git status` と `git diff` で差分に残っていないか確かめてください。** ここを戻し忘れると本番の共有機能が壊れます。2の `/etc/hosts` も消します。

撮影のシナリオで手こずったところを2つだけ書き残しておきます。ツールバーのアイコンだけのボタンは `title` 属性しか持たないので、文字では押せません（`button[title="えんぴつ"]` のように指定します）。それから、置いたスタンプの位置と大きさは、fabric.js の中身に触れずに知る必要があるので、置く前と置いた後のキャンバスの画素を見くらべて求めました。スタンプは中心を軸に拡大縮小されるため、角のつまみは中心からの距離で計算します。
